`main` is mostly written; you print the two result lines (or `Linear: not found after 7 comparisons` when the target is absent) and fill in the two functions. Both return the index or `-1`.

The one new thing is the counter. Each function receives `int *comparisons`, a **pointer** to the caller's counter. You do not need to understand pointers yet (that is week 6); you need one idiom: `(*comparisons)++;` adds one to the counter the caller gave you. Put that line right before every `if (numbers[...] == target)` and the counts come out right.

For binary search keep two indices, `low = 0` and `high = n - 1`, look at `middle = (low + high) / 2`, and move `low` or `high` past the middle depending on the comparison. The loop runs while `low <= high`. Trace the example by hand before you run it: 20, then 100, then 50; three comparisons.

Sort a list of numbers with the algorithm named on the command line and print the result on one line:

<Terminal lines={['make sort', './sort bubble']} out={`How many numbers? 5

Three things to do, in order:

1. **Validate** the argument exactly as in `caesar.c`: one argument, equal to `selection` or `bubble` (`strcmp(argv[1], "bubble") == 0`); otherwise print `Usage: ./sort selection|bubble` and `return 1`.
2. **Selection sort.** For each position `i` from 0 to n − 2, find the index of the smallest value from `i` to the end, then swap it into position `i`. A `swap` function that takes two pointers is already written for you; call it as `swap(&numbers[i], &numbers[smallest]);`.
3. **Bubble sort.** Up to n − 1 passes; in each pass compare every pair of neighbors and swap the ones in the wrong order. Keep a `bool swapped`; if a whole pass swaps nothing, `break`.

Print with a space between numbers and no trailing space: `printf("%i%s", numbers[i], i < n - 1 ? " " : "\n");` is one way. The tests try duplicates, negative numbers, a single number and a hundred random ones.

> [!tip] Test with the lecture's eight numbers
> `6 3 8 5 2 7 4 1` is the array from `selection.c` and `bubble.c` on the week page. If your output after each pass matches theirs, you have the algorithm; add a temporary `printf` inside the outer loop to compare, and remove it before you submit.

</Step>

`draw(n)` prints a left-aligned pyramid exactly like the lecture's `recursion.c`: if `n <= 0` return; otherwise `draw(n - 1)` first, then one row of `n` hashes. `factorial(n)` returns `n × (n − 1) × … × 1`: the base case is `factorial(0) = 1` (and 1 for n = 1), the recursive case is `n * factorial(n - 1)`. Use `long`, because 20! does not fit in an `int`; print it with `%li`. In `main`, re-prompt while the height or `n` is outside 0–20.

The checks also read your source: `factorial` must contain no `for` or `while`, and both functions must call themselves. Recursion is the point of this part, not an optional style.

> [!warning] Forgetting the base case
> Without `if (n <= 0) return;` the function calls itself forever and the program crashes with a segmentation fault. Write the base case first, then the recursive case.

## Troubleshooting

> [!note] My comparison counts are off by one
> Count exactly one comparison per element you look at, and increment before the `if`. Linear search for a present element at index i makes i + 1 comparisons.

> [!note] `./sort` sorts correctly but a test fails on the output format
> One line, single spaces, no trailing space, one newline at the end. Print nothing else after the numbers.

> [!note] Segmentation fault in `recursion`
> The base case is missing or wrong. `draw` must return when `n <= 0`; `factorial` must return 1 when `n <= 1`.

> [!note] `error: incompatible pointer types` when calling swap
> Pass addresses, not values: `swap(&numbers[i], &numbers[j])`, with the ampersands.
