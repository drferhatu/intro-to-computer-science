## Goal

By the end of this lab you have done the whole weekly loop once: accepted a lab, opened it in VS Code in your browser, written code, run the checks, pushed, and seen your score. Along the way you build a Scratch project and compile three C programs, one week before we study C properly. The C parts are scaffolded: you change one or two lines each.

> [!note] You can start without the instructor
> Everything you need is on this page. Work top to bottom. Ask your neighbor first, then the instructor. If one step blocks you for more than 10 minutes, write down the exact error message and go on to the next task.

> [!warning] First lab? Do the setup first
> You need a GitHub account and must have accepted the invitation to the course organization. If you have not, follow the [lab setup guide](/guides/lab-setup) (10 minutes), then come back here.

<Step n={4} title="Part A: a Scratch project" time="30 min" id="part-a">

Go to [scratch.mit.edu](https://scratch.mit.edu), sign in, click **Create**, and build a small program that has **all** of these:

- at least one **custom block** (*My Blocks → Make a Block*), for example `meow` or `bounce`;
- at least one **variable** that changes while the program runs (a score, a counter);
- at least one **loop** (`forever`, `repeat`, or `repeat until`);
- at least one **condition** (`if … then`);
- a reaction to the **user** (a key press, a click, or `ask … and wait`).

Ideas: a cat that meows every time you press space and counts the meows; a ball that bounces and scores when it touches a sprite; a quiz with three questions. Bigger is not better; working is better.

When it runs, click **Share**, then **Copy Link**. Open `README.md` in your codespace and replace the placeholder line so it reads:

```text
Scratch: https://scratch.mit.edu/projects/123456789/
```

> [!note] Why Scratch in a C course?
> Because your first C program next week will use the same five ideas, and it is easier to learn them without a compiler shouting at you. Every idea you used here has a C spelling in the [week 2 notes](/weeks/week-02#pseudocode).

</Step>

<Step n={5} title="Part B: hello, world" time="5 min" id="part-b">

Open `hello.c`. It is the program from the lecture with one word wrong. Fix the `printf` so it prints exactly `hello, world` followed by a newline. Then compile and run:

<Terminal lines={['make hello', './hello']} out="hello, world" />

`make hello` turns your source code into a program called `hello`; `./hello` runs it. If the compiler prints errors, read the **first** one: it names the line. Common ones: a missing semicolon, a missing closing quote.

</Step>

<Step n={6} title="Part C: greet the user" time="10 min" id="part-c">

Open `greet.c`. It asks for a name with `get_string` and stores it in a variable called `name`. The `printf` line is incomplete: make it print `hello, ` followed by the name and a newline. Hint: `%s` is the placeholder for a string, and the value goes after the format string, separated by a comma.

<Terminal lines={['make greet', './greet']} out={`What's your name? Firat
hello, Firat`} />

</Step>

<Step n={7} title="Part D: a byte as bits" time="10 min" id="part-d">

Open `bits.c`. It asks for a number from 0 to 255 and has a loop that walks over the 8 bits from left to right. The loop already computes `bit`, which is 1 or 0. Your job is one line: print the character `'1'` when `bit` is 1 and `'0'` otherwise. The `?` placeholders show you where.

<Terminal lines={['make bits', './bits']} out={`Number (0–255): 73
01001001`} />

Compare with the widget on the [week 2 page](/weeks/week-02): 73 is `I`. You just wrote, in C, the thing the widget does in JavaScript.

> [!try] Curious?
> Change the loop to print a space after every four bits, or print the number in hexadecimal too (`%x`). The checks only look at the exact 8-bit output, so keep the original program working.

</Step>

## Troubleshooting

> [!note] “This assignment isn't available to you” or “Not a member yet”
> You have not accepted the organization invitation. Check your email (and spam) for an invitation from **FiratUniversity-IJDP-SoftEng**, accept it, then refresh classroom50.org. See the [setup guide](/guides/lab-setup#troubleshooting).

> [!note] `make: clang: command not found`
> The codespace is still installing. Wait for the terminal to finish, or run `bash .devcontainer/setup.sh` once.

> [!note] `git push` says “rejected” or “fetch first”
> Someone (usually Classroom 50 itself) added a commit to your repository. Run `git pull`, then `git push` again.

> [!note] My score did not appear
> Open the **Actions** tab of your repository to watch the grading run. If it is still yellow, wait a minute. If it is red, click it and read the log, or show it to the instructor.

> [!note] `error: expected ';'`
> C ends every statement with a semicolon. The compiler names the line; the missing `;` is usually on the line **before** it.
