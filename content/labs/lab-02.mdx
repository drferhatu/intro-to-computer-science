<Step n={8} title="Part D · mario.c" time="20 min" id="part-d">

Write a program that asks for a height from 1 to 8, re-prompting until it gets one, and prints a right-aligned pyramid:

<Terminal lines={['make mario', './mario']} out={`Height: 4
   #
  ##
 ###
####`} />

Plan it before you type. Row 1 has three spaces and one `#`; row 2 has two spaces and two `#`; in general row `i` has `height - i` spaces and `i` hashes. So:

1. A `do … while` that asks for `height` until it is between 1 and 8 (lecture: `mario7.c`).
2. An outer `for` over the rows, `i` from 1 to `height`.
3. Inside it, one `for` that prints `height - i` spaces, then one `for` that prints `i` hashes, then `printf("\n")`.

> [!tip] Print a column first
> If the shape is wrong, simplify: print only the hashes (a left-aligned triangle), get that right, then add the spaces.

</Step>

<Step n={9} title="Part E · calculator.c" time="15 min" id="part-e">

Read two integers `x` and `y` and print five lines: the sum, the difference, the product, the quotient as a real number with two decimals, and the remainder. If `y` is 0, print the word `undefined` for the last two lines instead of dividing.

<Terminal lines={['make calculator', './calculator']} out={`x: 7
y: 2
9
5
14
3.50
1`} />

Two traps from the lecture: `x / y` with ints **truncates**, so cast first, `(float) x / (float) y`; and `printf("%.2f\n", z)` prints two decimals. Dividing by zero crashes a C program, so the `if (y == 0)` must come before the division.

</Step>

<Step n={10} title="Part F · cash.c" time="15 min" id="part-f">

Ask for an amount of change in cents (re-prompt while it is negative) and print the **minimum number of coins** using quarters (25), dimes (10), nickels (5) and pennies (1).

<Terminal lines={['make cash', './cash']} out={`Change owed: 41
4`} />

41 = 25 + 10 + 5 + 1. The strategy is **greedy**: always take the largest coin that still fits. Two ways to write it: a `while (cents >= 25)` loop per coin, or arithmetic: `cents / 25` is how many quarters fit and `cents % 25` is what is left. Both are correct; the second is four lines shorter. Try 0, 1 and 99 by hand before you trust the tests.

</Step>

## Other ways to work and submit

Codespaces is the easiest route, but it is not the only one. You can write your C **anywhere** and hand it in **from the browser**. Grading is exactly the same: every change that lands in your repository is graded automatically.

> [!warning] The CS50 library is not part of C
> `get_int`, `get_string` and the `string` type come from `cs50.h` and `cs50.c`, two files that are **in your repository**. Wherever you compile, those two files must sit next to your `.c` file, and `cs50.c` must be compiled together with it. Without them you get `cs50.h: No such file or directory` or `undefined reference to get_int`. The lab PCs and your own laptop do not have the library installed; cs50.dev does.

### Where you can work

| Option | What to do |
|---|---|
| **Your own computer** | Install a C compiler: macOS `xcode-select --install` in Terminal; Windows: [WSL](https://learn.microsoft.com/windows/wsl/install) then `sudo apt install gcc make`; Linux: `sudo apt install gcc make`. Download your repository (green **Code** button → **Download ZIP**), unzip, and in that folder compile each program **with the library**: `gcc -o mario mario.c cs50.c` then `./mario`. If `make` is installed, `make mario` does the same. For the checks, install Python 3 and `pip install pytest`, then `python3 check.py`. |
| **cs50.dev** | Open [cs50.dev](https://cs50.dev). The CS50 library is preinstalled there, so you can create `mario.c`, paste your code, and run `make mario` and `./mario` exactly as in the lecture. Copy your finished file back into your repository (below). |
| **Google Colab** | Open the lab notebook with the **Open in Colab** button below; a cell that starts with `%%writefile mario.c` saves your code, and `!gcc -o mario mario.c cs50.c && ./mario` compiles and runs it. ### Submit from the browser (no terminal, no git)

When a program is ready in a file on your computer or in another editor, put it into your repository on github.com in one of two ways.

**A. Paste into the file**

1. Open your repository `introduction-to-computer-science-lab02-yourusername` on github.com.
2. Click `mario.c`, then the **pencil icon ✎** (Edit this file) at the top right of the file.
3. Select everything (<span class="kbd">Ctrl</span> + <span class="kbd">A</span>, or <span class="kbd">⌘</span> + <span class="kbd">A</span> on a Mac) and paste your complete file.
4. Click **Commit changes…**, write a short message such as `Lab 2 mario`, keep **Commit directly to the main branch** selected, and click **Commit changes**.
5. Do the same for each file you changed.

**B. Upload the files**

1. On your repository page click **Add file → Upload files**.
2. Drag your `.c` files from your computer into the box. Files with the same name **replace** the starter files; that is what you want.
3. Click **Commit changes**.

> [!warning] Keep the names and the structure
> Paste or upload the **whole file**, keep the file names exactly `hello.c`, `greet.c`, `bits.c`, `mario.c`, `calculator.c`, `cash.c`, and keep `#include <cs50.h>` as it is: the autograder compiles with the library from the repository. Do not upload into a new folder; the files must stay at the top level. Do not upload compiled programs (`mario`, `a.out`), only source.

**Check your grade the same way.** About two minutes after each commit, a new **Release** with your score appears on the right of your repository page. Every commit counts as a submission, the last one before Friday 23:59 is the one that matters, and you may mix methods (for example, push from Codespaces on Monday and paste a fix from home on Wednesday).

## Troubleshooting

> [!note] Classroom 50 says “Not a member yet” or “This assignment isn't available to you”
> You have not accepted the organization invitation, or you are signed in with a different GitHub account than the one on the roster. Accept the invitation (step 1), then click **Check again**.

> [!note] `make: gcc: command not found` or `cs50.h: No such file`
> The codespace is still installing. Wait for the terminal, or run `bash .devcontainer/setup.sh` once. `cs50.h` is in your repository; `make` finds it with `-I.`.

> [!note] My score is lower than `python3 check.py` shows
> The autograder runs the official tests on the files you **pushed**. Save all files (File → Save All), check `git status` shows nothing left, then push again.

> [!note] `git push` is rejected
> Classroom 50 added a commit to your repository (the grading workflow). Run `git pull`, then `git push` again.

> [!note] My program waits forever
> It is waiting for input that never comes, or a loop never ends. Press Ctrl+C to stop it. Check the condition of your `do … while` and `for` loops.
